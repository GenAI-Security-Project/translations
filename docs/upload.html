Submit a finished English document for translation, or add locales or a new version to one that's already here (Process 1). It's done through a short form on GitHub, using your normal GitHub sign-in — no access token.

Who can submit

Translations managers only: members of the translations-managers team, people given Maintain on the translations repo, or org owners. Anyone else's request is refused automatically with a comment explaining why.

How it works

  1. Press Open the onboarding form below (you'll be asked to sign in to GitHub if you aren't).
  2. Choose A new document and drag the finished .pdf or .docx into the Source file box — or choose New locales or a new version and enter the existing document id from the Status page.
  3. Fill in the version and the locales (e.g. de-DE, es-ES), tick the public-file box, and press Create.
  4. Within a few minutes a comment on your issue links the onboarding pull request. Once it's reviewed and merged, each locale is machine-drafted from Actions → translate-draft.

The repository is public, so a file attached to the issue can be downloaded by anyone — only submit documents that are meant to be published. The file name becomes the document id, so name it clearly (e.g. OWASP-Top-10-for-LLM-Applications-2026.pdf).
