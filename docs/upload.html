There are two short forms on GitHub, both using your normal GitHub sign-in — no access token:

  • Onboard a new document — a finished English document that isn't here yet, with its file attached (below).
  • Add languages to a document — for a document that's already here: pick it and the languages from lists, no file needed. Easiest from + Add languages on the Status page, or open the form directly. Drafting starts straight away.

Who can submit

Translations managers only: members of the translations-managers team, people given Maintain on the translations repo, or org owners. Anyone else's request is refused automatically with a comment explaining why.

Onboarding a new document

  1. Press Open the onboarding form below (you'll be asked to sign in to GitHub if you aren't).
  2. Drag the finished .pdf or .docx into the Source file box.
  3. Enter the version, choose the languages and the layout template from the lists, tick the public-file box, and press Create.
  4. Within a few minutes a comment on your issue links the onboarding pull request. Once it's reviewed and merged, each locale is machine-drafted automatically, one pull request per locale.

The repository is public, so a file attached to the issue can be downloaded by anyone — only submit documents that are meant to be published. The file name becomes the document id, so name it clearly (e.g. OWASP-Top-10-for-LLM-Applications-2026.pdf).
